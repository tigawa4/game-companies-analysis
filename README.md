# ゲームメーカー3社の収益性・利益構造比較

任天堂株式会社・株式会社カプコン・株式会社コーエーテクモホールディングスの損益と収益性を比較する分析プロジェクトです。

出典はEDINETの有価証券報告書から取得した日本基準の連結財務データです。

SQLによる分析用データの作成と、Tableau Publicによる可視化を行っています。

## 想定利用者と目的

想定利用者は、架空の大手ゲームメーカーの経営企画・財務担当者です。

他社の収益性・利益構造を明らかにすることで、自社の戦略立案や課題発見につなげることを目的としています。

ただし、架空の自社データを用意していないため、他社の分析を主目的としています。

## データ処理の流れ

1. Python製ETLで「EDINET API」から書類を取得し、「PostgreSQL」へ格納
2. DBスキーマからテーブル定義書・ER図を生成してデータ構造を確認
3. SQLで連結損益計算書のデータを抽出し、分析用テーブル・ビューを作成
4. SQLで百万円換算、利益率、前年比増減率、比率の前年差を計算
5. SQLクライアントツール「Beaver」からCSVを出力
6. 「Tableau Public」でダッシュボードを作成

## 今後の課題

### 可視化手法の振り返り
散布図では、利益率・費用比率・売上高成長率を組み合わせ、企業ごとの相対的な位置関係を把握することを意図しました。

企業ごとの利益・費用構造の違いが、散布図上のまとまりとして表れることを期待しました。

しかし今回試した指標の組み合わせでは、比較表や時系列グラフを超える追加の知見は限定的でした。

今回の分析では、年度ごとの変化は時系列グラフ、企業ごとの指標の分布は個別プロットを中心に確認し、散布図は二つの指標を同時に比較する補助的な位置づけとしました。

### データの理解
contexts.dimensionsやunitsテーブルの単位情報は、URIを含む識別子をJSON形式で保持しています。

AIレビューを受け、「地域別などの追加区分を持たない」「金額の単位が円である」という抽出条件をクエリに追加し、対象データを抽出できることを確認しました。

これらの情報は識別子だけでは意味を把握しにくいため、区分有無や通貨単位を表示するビューを用意し、分析者が抽出条件を指定しやすくする改善が考えられます。

XBRLの区分・単位情報やJSONの扱いへの理解を深める必要があります。

## まとめ
今回のダッシュボードは、年次財務データによる中長期的な収益性・利益構造の比較を目的としています。

今後は日次など更新頻度の高いデータも対象とし、状況の変化をタイムリーに把握できるダッシュボードの構築に取り組みたいと考えています。
